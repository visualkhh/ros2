# 2026-10-28 — state_manager · cmd_manager(mux) · RL 실행 중 전환

## 1. 바퀴 명령 구조 변경

- 전: 드라이버가 `cmd_vel`(tb-only) 또는 `cmd_vel_rl`(tb-for-rl)을 직접 받음. RL을 켜고 끄려면 bringup을 다시 띄워야 했고,
  텔레오퍼와 Nav2가 같은 `/cmd_vel`에 섞여 들어감.
- 후: **state_manager**(상태의 주인: `/state_mode` MANUAL·AUTO · `/state_rl` · `/state_estop`, latched)와
  **cmd_manager**(mux: 상태대로 수동 `/cmd_manual_vel` 또는 Nav2 `/cmd_vel`을 골라 바로 `/cmd_vel_base`로,
  RL on이면 `/cmd_vel_rl_in` → PC → `/cmd_vel_rl_out` → `/cmd_vel_base`). 외부 요청은 `/cmd_manual_*`.
- 모드 자동 전환: tool 텔레오퍼·drive → MANUAL, tool goal·RViz Nav2 Goal(`/goal_pose`) → AUTO.
- 안전: 비상정지 → 0 · 고른 입력 0.5초 끊김 → 0 · RL on인데 PC 보정값 0.3초 끊김 → 0.
- 도면: [ARCH.md 2장](../../ros2_ws/ARCH.md).

## 3. 시행착오

- 시험 중 CLI가 매번 새로 떠서 latched `/state_mode`를 받기 전에 모드를 비교 → 이미 MANUAL인데 MANUAL 요청을 한 번 더 보냄
  (결과엔 영향 없음). → 상태 수신을 최대 2초 기다린 뒤 비교.
- 실기(도메인 25)와 섞이지 않게: 시험은 도메인 84 + `ROBOT_HOST=nohost.local`(Pi 피어 끔) + `TOOL_LOCAL=1`.
  `cli/start.sh`의 도메인을 잠깐 바꾸고 `trap`으로 25로 되돌림.

## 4. tool을 어디서나 (로봇에 붙지 않아도)

- 지적: 문서가 "Pi에 ssh해서 run-cli" 식이었고, PC에서 베이스·SLAM·Nav 시작은 거부하게 만들어 둠. 토픽이 보이면 다 돼야 맞음.
- 실제로 토픽만으로 안 되는 건 **프로세스 켜기/끄기**와 **지도 파일**(로봇에 있어야 Nav가 읽음)뿐.
- 해결: 로봇이 아닌 곳에서는 `RemoteProcs`가 켜기/끄기/재시작·로그·지도 저장/목록/내용을 **SSH로 로봇의 run-cli**에 넘기고,
  켜짐 표시(●/○)는 **ROS 노드 그래프**(opencr_driver·cartographer_node·amcl·bt_navigator)로 판단. PC에서 SLAM 시작·재시작·정지 실기 확인.
- 시행착오: SSH가 PC 사용자(`pank@pak.local`)로 붙어 `Permission denied` → 대상 `pak@pak.local` (`TOOL_ROBOT_SSH`).

## 5. tb-for-rl 삭제

- mux 이후 tb-only와 tb-for-rl의 차이는 시작할 때 `/state_rl` 값 하나뿐 (둘 다 RL 노드 없음). 이름이 "RL을 같이 띄운다"로 읽혀 혼동 → 삭제.
- RL on으로 시작: `tb-only.launch.py rl:=true` · 보통은 실행 중 `./run-cli rl on`.

## 6. 제어 상태 · 운행 상태 · 자동 맵핑 · mock 제거

- 역할: **cmd_manager**가 외부 요청(`/cmd_manual_control`·`_rl`·`_estop`, RViz `/goal_pose`)을 받아 상태 변경을 판단 → `/state_set_*` → **state_manager**는 `/state_*`로 알리기만.
- **제어 상태** `/state_control`: MANUAL · NAV_PLAN · SLAM_AUTO_MAPPING (수동 명령은 MANUAL에서만). **운행 상태** `/state_operation`: SLAM · LOCALIZATION · IDLE (떠 있는 노드로 판단) · `/state_map`: 적용된 지도.
- 자동 맵핑 `frontier_explorer` (numpy, apt에 탐색 패키지 없음). 시뮬에서 SLAM 막 켠 직후 첫 지도에 빈 칸이 없어 바로 "완료" 처리 → frontier 없음이 10초 계속돼야 완료로.
- CLI: 수동 주행은 MANUAL 아니면 물어봄 — 스크립트(비TTY)에서 입력 대기로 멈춤 → 비TTY는 묻지 않고 거부.
- `mock_base`·`basic_bringup` 삭제 (PC 시험용 더미). OpenCR 없는 PC 주행 시험 수단은 이제 없음.

## 7. cartographer 소스 빌드 실패 (abseil 신형) → SLAM 전환

- 증상: `colcon build`에서 `cartographer` 코어·`cartographer_ros_msgs`는 성공, `cartographer_ros`만 실패.
  `install/cartographer_ros`에 파일 6개(`share/.../package.*`뿐, `lib/` 없음). 에러:
  `map_builder_bridge.h:97: error: expected ';' ... LOCKS_EXCLUDED(mutex_)` 외 `GUARDED_BY`·`EXCLUSIVE_LOCKS_REQUIRED` 동일 계열 수십 개.
- 원인: Pi의 libabsl-dev `20260107.0`이 접두어 없는 구 매크로(`GUARDED_BY` 등)를 제거 → `ABSL_` 접두어 필수.
  기존 `patches/cartographer-ceres2.patch`는 `src/cartographer` 코어만 고치고 `src/cartographer_ros`는 안 고침.
- 해결: `patches/cartographer_ros-ceres2.patch` 신규 — `cartographer_ros` 5파일 + `cartographer_rviz` 2파일(`drawable_submap.h`·`submaps_display.h`)의
  매크로를 `ABSL_GUARDED_BY`·`ABSL_LOCKS_EXCLUDED`·`ABSL_EXCLUSIVE_LOCKS_REQUIRED`로 전환. 적용:
  `cd src/cartographer_ros && patch -p1 < ../../patches/cartographer_ros-ceres2.patch`
  (`src/`는 `.gitignore`라 `pull`로 안 넘어옴 — 패치 파일이 정본, 바뀔 때마다 재적용).
- SLAM 전환: `slam_toolbox` → cartographer. `tb3_bringup/config/cartographer_2d.lua`
  (LDS-03 min 0.12 m · max 8 m · `/odom` 사용 · `map→odom` 발행) + `launch/cartographer.launch.py`
  (`cartographer_node` + `cartographer_occupancy_grid_node`, `/scan`·`/odom` 리맵) 신규.
  `tool/cli/op/procs.py`의 `slam` 명령·감지 노드(`slam_toolbox` → `cartographer_node`) 변경.
- 교훈: 외부 소스 패치는 **같은 저장소 안의 전 패키지**(`cartographer_ros`+`cartographer_rviz`)까지 grep으로 확인.
  `grep -rn 'GUARDED_BY\|LOCKS_EXCLUDED' src/cartographer_ros | grep -v ABSL_`가 빌드 전에 비어야 함.

## 8. cartographer 재빌드 실패 2건 (CMake 4 · 패치 중복 적용)

- 증상 1: `colcon build --packages-select cartographer ...`가 0.7초 만에 실패.
  `CMake Error at CMakeLists.txt:15 (cmake_minimum_required): Compatibility with CMake < 3.5 has been removed from CMake.`
- 원인 1: Ubuntu 26.04의 CMake 4.x가 `<3.5` 하위 호환을 제거. cartographer 코어의 `cmake_minimum_required`가 구버전이라 configure 단계에서 바로 걸림 (abseil 패치 문제 아님).
- 해결 1: 소스를 고치지 않고 configure 플래그로 우회:
  `colcon build --symlink-install --parallel-workers 2 --packages-select cartographer cartographer_ros_msgs cartographer_ros --cmake-args -DCMAKE_POLICY_VERSION_MINIMUM=3.5`
  (전체 빌드에도 같은 `--cmake-args`를 붙임. `lyrical-setup` 4장 반영)
- 증상 2: 패치 재적용 시 `1 out of 1 hunk ignored -- saving rejects to file cmake/functions.cmake.rej`.
  이어서 `(cd src/cartographer_ros && ...)`가 `No such file or directory` + 뒤 grep도 같은 에러.
- 원인 2: (a) 이미 적용된 패치를 또 쳐서 reject 발생, (b) `~/ros2/ros2_ws/src/cartographer` 안에서 `cd src/cartographer_ros`를 쳐서 상대경로가 어긋남.
- 해결 2: 반드시 `~/ros2/ros2_ws`에서 실행. reject가 생겼으면 각 폴더를 원복 후 재적용:
  `git -C src/cartographer checkout -- . && git -C src/cartographer clean -f` (ros도 동일) →
  `(cd src/cartographer && patch -p1 < ../../patches/cartographer-ceres2.patch)` →
  `(cd src/cartographer_ros && patch -p1 < ../../patches/cartographer_ros-ceres2.patch)`.
- 교훈: `patch --forward`의 `ignored`는 "이미 적용됨" 신호일 수 있음. `.rej`가 생기면 무작정 다시 치지 말고 원복 후 1회만 적용.

## 9. `multirobot_map_merge` 빌드 실패 (`image_geometry` 없음)

- 증상: `colcon build`에서 `cartographer`·`cartographer_ros_msgs`·`coin_d4_driver`·`explore_lite`는 성공,
  `Failed <<< multirobot_map_merge` + `Aborted <<< cartographer_ros` (2개 미처리).
  에러: `Could not find a package configuration file provided by "image_geometry"`.
- 원인: `deps.repos`의 `m-explore-ros2`에 우리가 쓰는 `explore_lite` 외에 `multirobot_map_merge`도 딸려 오는데,
  얘는 `image_geometry` apt 의존이 있음. 2장 apt 목록에 없어서 깨짐. `cartographer_ros`는 직접 의존이 없는데
  병렬 빌드 중단 여파로 abort됨 (재빌드하면 붙음).
- 해결: `sudo apt install -y ros-lyrical-image-geometry` 또는
  `rosdep install --from-paths src --ignore-src -r -y` 후 재빌드.
  급하면 `colcon build ... --packages-skip multirobot_map_merge` (우리는 `explore_lite`만 씀).
- 반영: `lyrical-setup` 2장 apt 목록 + 4장 `rosdep install` 단계 + 4-1 표에 추가.

## 10. `multirobot_map_merge` configure 실패 (`ament_target_dependencies` 없음)

- 증상: `image_geometry`를 깔고도 `CMake Error at CMakeLists.txt:101 (ament_target_dependencies): Unknown CMake command`로 실패.
  같은 로그의 `cartographer`·`coin_d4_driver`·`explore_lite` Deprecation 경고는 무해 (빌드 성공).
- 원인: Lyrical의 `ament_cmake` 2.8.8은 `ament_target_dependencies()`를 더 이상 딸려 주지 않음
  (`ament_cmakeConfig.cmake`의 extras가 `ament_cmake_export_dependencies` 하나뿐 — 매크로는 분리된
  `ament_cmake_target_dependencies` 패키지에 있음). `explore_lite`·`coin_d4_driver`는 그 매크로를 안 써서 붙었고,
  쓰는 `multirobot_map_merge`(m-explore-ros2 @ `326cf8a`)만 걸림. abseil·image_geometry 문제 아님.
- 해결: `ros2_ws/patches/m-explore-ros2-ament-target-deps.patch` 신규 —
  `map_merge/CMakeLists.txt`에 `find_package(ament_cmake_target_dependencies REQUIRED)` 1줄 +
  `map_merge/package.xml`에 `buildtool_depend` 1줄. `setup/pi/build.sh`가 자동 적용
  (대시 포함 저장소명 매핑 `m-explore-ros2-*` → `src/m-explore-ros2` 수정 포함).
- Pi에서: `cd ~/ros2 && git pull && ./setup/pi/build.sh` (1단계에서 외부 소스 원복 후 3종 패치 재적용됨).
  당장 깨진 `build/` 캐시만 치우고 싶으면 `rm -rf build/multirobot_map_merge` 후 재빌드.
- 교훈: "Unknown CMake command ament_*"는 의존 빠짐이 아니라 **Lyrical의 매크로 분리**를 의심.
  `/opt/ros/lyrical/share/ament_cmake/cmake/ament_cmakeConfig.cmake`의 `_extras` 목록으로 확인.
