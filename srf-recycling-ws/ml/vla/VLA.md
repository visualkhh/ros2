# VLA 정리 노트 — 우리가 무엇을, 왜, 어떻게 하고 있나

> 2026-11-29 대화를 정리한 노트다. 학습하면서 계속 덧붙인다. 실행 방법은 [README.md](README.md).
> 짝 문서: [../vlm/VLM.md](../vlm/VLM.md) (VLA 는 VLM 을 "눈과 머리"로 쓴다)

---

## 0. 한 줄 요약

카메라 영상 + 지시 + 로봇 상태를 보고 **로봇이 움직일 수 있는 모든 것**(바퀴·팔 관절 4개·그리퍼·부저)을 앞으로 2초 분량씩 내는 정책이다.
선별장 물체를 이미 아는 **우리 VLM 을 얼려서 눈과 머리로 쓰고**, 그 뒤에 **작은 행동 헤드**만 시뮬레이터 조교의 시범으로 학습한다. CPU 로 학습·추론한다.

---

## 1. VLA 는 뭐고 VLM 과 뭐가 다른가

| | VLM | VLA |
|---|---|---|
| 이름 | Vision-Language Model | Vision-Language-**Action** Model |
| 입력 | 이미지 + 글 | 이미지 + 글 + **로봇 상태** |
| 출력 | 글 (JSON) | **모터 명령** (숫자) |
| 하는 일 | "무엇이 어디 있나, 무엇을 집을까" | "그래서 바퀴·관절을 지금 어떻게 움직일까" |
| 속도 요구 | 고를 때 한 번 (수 초 OK) | 끊기지 않게 (4 Hz, 청크로) |

비유: VLM = 상황을 보고 이해하는 **눈과 머리**, 행동 헤드 = 손발을 움직이는 **운동 신경**.

## 2. 목표에서 정한 것

목표: 실기 로봇이 지시대로 물체에 다가가 집어서, 맞는 바구니 앞에서 다가가 놓는다. CPU 만 쓴다.

### 2.1 출력 = 로봇이 움직일 수 있는 모든 것

하드웨어 인터페이스(`OpenCrDevice`)가 받는 명령 전부에서 골랐다.

| 출력 | 실기 명령 | 왜 VLA 가 내나 |
|---|---|---|
| 바퀴 v, ω | `write(Twist)` | 팔 작업 범위가 로봇 앞 약 15~30 cm 로 좁다. Nav2 는 근처(오차 5~10 cm)까지만 → 마지막 몇 cm 는 **영상을 보며** 바퀴로 붙어야 한다 |
| 팔 j1~j4 | `write_arm` | 집기·놓기 |
| 그리퍼 | `write_arm` 5번째 | 쥐기·놓기 |
| 부저 | `buzzer` | 움직이기 시작할 때, 사람이 다가올 때 알림 |

뺀 것: 토크 on/off, 모터 재부팅 — 움직임이 아니라 정비·복구. 모델이 토크를 끄면 팔이 떨어진다 → 안전 계층이 맡는다.

좌·우 바퀴 속도 대신 (v, ω) 를 쓰는 이유: 차동 구동이라 1:1 로 같은 정보이고, 실기 명령(`Twist`)이 이 형태다.

### 2.2 입력 — 기준 두 개

1. **다음 동작에 정보가 되나?**
2. **실기에서도 똑같이 얻을 수 있나?**

쓸모없는 입력을 넣으면 적은 데이터에서 모델이 우연한 상관에 기댄다 (인과 혼동 / copycat). 예: 시뮬 데이터에서 "바퀴가 멈춰 있을 때만 팔이 움직였다" → 실기에서 바퀴 값이 조금 흔들리면 팔이 멈칫.

| 입력 | 이유 |
|---|---|
| 지시 문장 | 무엇을 할지 (집기/넣기, 종류) |
| RGB | 물체 모양·자세, 그리퍼와 물체의 상대 위치 |
| 깊이 | 거리·높이·누움/섬 (32×24 격자로 줄여서) |
| 차체 속도 (odom v, ω) | 바퀴를 직접 내니 지금 얼마나 움직이는지 필요 |
| 관절 위치·속도 | 지금 팔이 어디 있고 어디로 가는 중인지 |
| 관절·그리퍼 전류 | **쥐었는지**(덜 닫혔는데 전류 높음), 어딘가 **걸렸는지** |
| 엔드이펙터 자세 | 관절에서 FK 로 계산되는 같은 정보지만, 모델이 FK 를 배우지 않아도 되게 |
| 앞쪽 장애물 거리 (라이다 ±20°) | 다가가다 매트·바구니에 부딪히지 않게 |
| 대상 3D 위치 | VLM 이 고른 bbox → 깊이 → TF → base_link. 발제의 "3D 위치"를 VLA 목표로 연결 |
| 바구니 위치 | map_marker → TF → base_link. **map_marker 가 VLA 에도 쓰인다** |

넣지 않는 것: map/odom 자세(로봇 기준 상대 위치만 필요), 카메라→base TF(고정, 상수), 모터 온도·에러(안전 감시 몫).

## 3. 구조 — VLM 을 얼리고 헤드만 학습

```
RGB + 지시 ─▶ [VLM: ml/vlm 에서 미세조정, 얼려 둠] ─▶ 장면 이해 벡터 (576)
깊이 ─▶ 32×24 격자 ─▶ 작은 층 (128) ─────────────────────────┐
로봇 상태 29개 (정규화) ──────────────────────────────────────┼─▶ 행동 헤드 (MLP) ─▶ 8 스텝 × 8 출력
장면 이해 벡터 ───────────────────────────────────────────────┘
```

| 방법 | 장점 | 문제 |
|---|---|---|
| A. VLM 전체를 미세조정해 행동을 **글자로** | 모델 하나 | CPU 로 답 하나에 수 초 → 팔이 끊김, 숫자 정밀도 약함 |
| **B. VLM 얼리고 행동 헤드 (택함)** | 물체 이해 재사용, 출력 빠르고 정밀, CPU 학습 | VLM 이 물체를 잘 알아봐야 함 → VLM 학습이 먼저 |
| C. VLM 없이 작은 CNN 정책 | 가장 빠름 | 말(지시)을 못 알아들음, "VLA" 조건이 약함 |

**행동 청크**: 한 번에 앞으로 8 스텝(4 Hz × 2초)을 낸다. 매 스텝 새로 묻지 않아도 되고(CPU 절약), 떨림이 줄어든다. 엔진은 몇 스텝 실행하고 최신 관측으로 다시 묻는다.

**왜 장면 이해 벡터를 미리 계산하나** (`features.py`): VLM 은 얼려 두니 같은 입력이면 같은 벡터 → 한 번만 계산해 저장하고, 학습은 작은 헤드만 수십 에폭 돌린다. VLM 을 매번 돌리면 CPU 로 수십 배 느리다.

**손실**: 연속값(v, ω, 관절, 그리퍼)은 smooth L1, 부저는 켬/끔 확률(BCE). 회차 끝을 넘는 청크 칸은 마스크로 뺀다.

**정규화**: 데이터 통계가 아니라 **물리 범위**로 고정(`data.py`). 실기·새 데이터셋에서도 같은 숫자 → 배포가 단순하다.

## 4. 시범 데이터 — 시뮬레이터 조교

사람이 수천 번 조종할 수 없으니 시뮬레이터가 **진실값을 보고 직접 모는 조교**가 시범을 보인다 (`srf_recycling_ws_vla_demos`, C++, `simulator/tools/vla_demos.cpp`).

- 생성기는 시뮬레이터 내부(월드·물리·렌더러)가 필요해서 `simulator/tools` 에 있다 (VLM 데이터 생성기와 같은 이유). `ml/vla` 는 그 결과를 읽어 학습한다.
- **실기와 같은 경로**: 명령은 실기와 같은 `OpenCrDevice` 로 내리고, 영상은 같은 `SimulatorRealSense` 로 받는다. 엔진이 실기에서 받는 값과 형식이 같다.
- **물리 그대로**: 팔 충돌(자기 몸·카메라·마운트·바닥), 쥐기·놓기, 자유낙하, 바구니 안 판정, 바닥 낙하 판정.

```
pick : 매트 근처 아무 데서 → 바퀴로 다가감 → 물체 위 → 내려감 → 닫음 → 들어 올림 → 들고 다니는 자세
place: (Nav 이동은 순간이동으로 대신) 바구니 앞 → 다가감 → 바구니 위 → 엶 → 물러남
```

- 조교는 **닫힌 루프**: 매 스텝 진실값을 다시 본다 (밀린 물체도 따라간다).
- **대상 위치 추정 오차**를 일부러 넣는다: 회차마다 고정 편향(σ 8 mm) + 스텝 잡음(σ 4 mm). 실기에서 VLM+깊이가 완벽하지 않으니까.
- **DART** (틀어졌을 때 되돌아오는 법): 일부 회차는 스텝의 30% 에서 실행 행동에 잡음, 라벨은 조교의 깨끗한 행동.
  처음에 매 스텝 잡음을 넣었더니 팔이 목표 근처에서 늘 흔들려 "도착"을 못 해 절반이 실패 → 30% 로 바꾸니 24/24 성공.
- 성공한 회차만 학습에 쓴다 (실패 회차는 채점·분석용으로 남는다).

### 기록 한 스텝 (`steps.jsonl`)

```json
{"step":12, "phase":"descend", "rgb":"rgb/012.jpg", "depth":"depth/012.png",
 "state":{"odom":{"v":0,"w":0}, "wheels":{...}, "arm":{"position":[5],"velocity":[5],"current":[5]},
          "ee":[x,y,z,pitch,yaw], "scan_front_min":0.41, "target_xyz":[...], "bin_xyz":[...]},
 "truth":{"target_xyz":[...], "holding":false, "blocked":"", "person_min":3.2, "robot":[x,y,θ]},
 "action":{"v":0,"w":0,"joints":[4],"gripper":0.019,"buzzer":0}}
```
`state` = 모델 입력(실기에서도 있는 값), `action` = 정답, `truth` = 채점용(실기엔 없음, 모델에 안 넣는다).

## 5. 시뮬레이터에서 고친 것 (VLA 를 위해)

| 무엇 | 왜 |
|---|---|
| 팔 충돌 (실제 STL 메시, SRDF 비검사 쌍) | 팔이 몸·카메라를 뚫으면 실기에서 안 되는 시범을 배운다 |
| 접은 자세 link2–link5 접촉 허용 (SRDF User) | 실기에서 일부러 살짝 기대게 해 둠 |
| 관절 속도·전류 근사 | 실기 Dynamixel 이 주는 값. 쥠(그리퍼 0.45 A)·걸림(정지 전류 0.9 A)을 배우게 |
| 장면 바꿀 때 쥔 물체 정리 | 사라진 물체를 가리켜 죽는 문제 |

전류는 **근사**다 (중력 토크·가속 미반영). 실물 로그로 계수를 맞춰야 한다.

## 6. 평가

- **오프라인** (`evaluate.py`): 검증 회차에서 조교 행동과의 차이 — v·ω·관절·그리퍼 오차(물리 단위), 그리퍼 열림/닫힘·부저 일치, 단계별 관절 오차.
- **닫힌 루프** (다음): 조교 대신 정책을 시뮬레이터에 넣어 직접 몰게 하고 집기 성공률·넣기 성공률·충돌·낙하를 센다. 오프라인 오차가 작아도 닫힌 루프에서는 오차가 쌓일 수 있어서 이게 진짜 점수다.
- **실물** (발제): VLA 담당 동작의 실행 결과, 배치 오차, 집기 실패·낙하. 원출력·변환값·거부 여부를 기록.

## 7. 진행 기록

| 단계 | 결과 |
|---|---|
| 입출력 결정 | 출력 8개 (v, ω, j1-4, 그리퍼, 부저), 입력 29개 상태 + RGB + 깊이 + 지시 |
| 시범 생성기 | 약 4 s/회, 6 MB/회. 일반 16/16, DART 24/24 성공 |
| 학습 코드 (`ml/vla`) | data → features → train → evaluate → export_onnx 를 작은 데이터로 끝까지 확인 (VLM 특징 0.47 s/스텝, ONNX 와 torch 차이 1e-7) |
| 다음 | VLM v1 학습이 끝나면 → 시범 1000회 → 특징 → 헤드 학습 → 닫힌 루프 채점 |

## 8. 알고 있는 한계

- **sim-to-real**: 시뮬 영상·물리와 실물은 다르다. 실물 시연 소량으로 미세조정, 시뮬·실물 점수를 따로 센다.
- **Nav 순간이동**: place 시작 자세는 Nav 가 데려다 놓는다고 가정. 실제 Nav 오차 분포로 시작 자세를 뽑는 게 다음.
- **깊이 표현**: 32×24 격자는 거칠다. 작은 물체 정밀 집기가 모자라면 대상 중심 깊이 크롭 + 작은 CNN.
- **그리퍼 폭**: 시뮬은 닫으면 끝까지 닫힌다 (물체 폭에서 멈추지 않는다). 실기는 물체 폭에서 멈추고 전류가 오른다.
- **조교 행동 = 상한**: 정책은 조교보다 잘하기 어렵다. 조교 자체가 서툰 곳(바구니 IK 경계 등)은 조교를 먼저 고친다.

## 용어

| 용어 | 뜻 |
|---|---|
| 정책 (policy) | 관측 → 행동을 내는 모델 |
| 행동 청크 | 한 번에 내는 앞으로 여러 스텝의 행동 |
| 모방 학습 / BC | 조교(전문가)의 행동을 따라 하도록 배우는 것 (Behavior Cloning) |
| DART | 실행에 잡음을 넣어 틀어진 상태와 그때의 올바른 행동을 모으는 방법 |
| 닫힌 루프 | 매 스텝 새 관측을 보고 다시 판단하며 실행하는 것 |
| 특징 캐시 | 얼린 모델의 출력을 미리 계산해 저장해 두는 것 |
| odom | 바퀴 회전으로 계산한 로봇 이동 (속도·자세) |
| FK | 관절 각도 → 손끝 위치 계산 |
